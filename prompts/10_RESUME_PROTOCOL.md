# 🔄 RESUME PROTOCOL — برومت استئناف الجلسة

> **متى تستخدمه:** عندما يتوقف الـ AI في منتصف العمل (Context limit, نهاية session, خطأ شبكة) وتفتح **سيشن جديد**.

---

## 📥 خطوات استخدامك (المستخدم)

1. **افتح سيشن جديد** في Kiro / Claude / GPT.
2. **ألصق MASTER PROMPT** أولاً (`00_MASTER_PROMPT.md`).
3. **ألصق هذا البرومت (RESUME PROTOCOL)** ثانياً.
4. **ألصق آخر `STATE_SNAPSHOT` JSON** الذي طبعه الـ AI قبل التوقف.
5. **(اختياري)** ألصق آخر 80-120 سطر من الكود الذي أنتج، حتى يفهم السياق المباشر.
6. اكتب: `استأنف من حيث توقفت`.

---

## 🤖 برومت الاستئناف (انسخه أنت)

```
أنت في وضع RESUME.
أنا أستأنف عملاً سابقاً على منصة التدريب الاحترافية (single-file HTML offline).
MASTER PROMPT محمّل بالأعلى — لا تخالف قواعده.

المعطيات:
1) STATE_SNAPSHOT الأخير:
<ألصق هنا الـ JSON>

2) آخر مقتطف من الكود (لمحاذاة السياق):
<ألصق آخر 100 سطر — اختياري>

3) الملاحظات الإضافية إن وُجدت:
<مثلاً: "اكتشفت bug في X" أو "غيّرت أولوية Y">

تعليمات لك:
─ لا تعد العمل المُنجَز — ابدأ من Phase التالي مباشرة.
─ افحص أن الـ open_threads كلها مغلقة قبل التقدم. إذا كان هناك thread مفتوح غير محلول، عالجه أولاً.
─ ابدأ ردك بـ:
   ▶️ RESUMING — Worker: <id> from Phase <x+1>
   📌 Verified state: <ملخص ما تأكدت منه>
   🎯 Now proceeding with: <اسم Phase>
─ اعمل في حدود ≤ 800 سطر للـ phase الواحد.
─ اختم بـ CHECKPOINT + STATE_SNAPSHOT جديد.

ابدأ الآن.
```

## 🛟 حالات خاصة للاستئناف

### الحالة 1: الـ STATE_SNAPSHOT ضائع
إذا فقدت الـ snapshot:
1. استخدم **Resume Recovery Prompt** التالي:

```
لقد فقدت آخر STATE_SNAPSHOT. ساعدني في إعادة بناء السياق.
سأعطيك:
- اسم الـ Worker الذي كنا نعمل عليه: <مثلاً: 02 — Sales>
- آخر phase أتذكر إنه اكتمل: <رقم تقريبي>
- الملف الحالي مرفق (أو سأعطيك أسماء الـ id الموجودة في `<section>`)

افحص الملف:
1) عدّ كم phase اكتمل فعلاً عبر البحث عن العلامات.
2) أعطني snapshot مُعاد بناؤه مع توضيح ما اكتمل وما لم يكتمل.
3) اقترح Phase التالي.
```

### الحالة 2: الكود ينقصه أجزاء (تم قطعه في الوسط)
إذا الـ AI قُطع وهو يكتب كود في منتصف function:

```
آخر function أنتجتها قُطعت في منتصفها. الجزء المكتمل:
<ألصق الجزء>

أكمل **فقط** هذه الـ function من حيث توقفت — لا تعيد كتابة الجزء الموجود.
بعد الانتهاء، تابع الـ phase الحالي.
```

### الحالة 3: تغيير المتطلبات في منتصف العمل
إذا قررت تعدّل شي:

```
تغيير في النطاق:
- الإضافة الجديدة: <واضحة>
- ما يُحذف من الخطة: <واضح>
- التأثير على الـ phases المتبقية: <اشرح>

أعد ترتيب الـ phases المتبقية حسب التغيير، ثم استأنف من Phase <الحالي/التالي>.
```

### الحالة 4: تضارب بين Workers
لو شعرت أن Worker جديد يعارض شغل Worker سابق:

```
اكتشفت تضارب محتمل:
- Worker السابق <id>: <ما عمل>
- Worker الحالي <id>: <ما يحاول أن يعمل>
- نقطة التضارب: <واضحة>

قبل الاستمرار:
1) حلّل التضارب.
2) اقترح حلاً (دمج / استبدال / فصل).
3) انتظر تأكيدي.
```

## 🧬 STATE_SNAPSHOT Schema (للمرجع — كي تتعرف عليه عند نسخه)

```json
{
  "worker": "<id-name>",
  "phase_completed": <int>,
  "phases_total": <int>,
  "files_touched": ["<file paths>"],
  "lines_added_total": <int>,
  "next_action": "<وصف خطوة قادمة>",
  "open_threads": ["<مهام معلقة>"],
  "design_tokens_used": ["<--var-1>", "<--var-2>"],
  "citations_added": <int>,
  "localStorage_keys_added": ["<key>"],
  "known_issues": ["<مشاكل لم تُحل بعد>"],
  "next_worker_recommended": "<id أو null>"
}
```

أي حقل ناقص في snapshot يُعتَبر "غير معلوم" ويُعالَج بـ Resume Recovery.

## 💡 ممارسات تمنع الانقطاع من الأساس

1. **اطلب من الـ AI** يطبع `STATE_SNAPSHOT` بعد كل phase دون أن تنسى.
2. **احفظ الـ snapshots** كل واحد في ملف `.json` (أو notes).
3. **لا تطلب أكثر من phase واحد في الردّ الواحد** — حتى لو كان مغرياً.
4. **شطر الـ Workers الكبار** لـ phases أصغر (300-500 سطر بدل 800).
5. **بعد كل 3 phases** — افتح سيشن جديد طوعياً قبل ما يقطع.
6. **استخدم Compaction** إذا الـ tool متوفر (مثلاً Kiro يدعم).

---

## 🆘 إذا انقطع المساعد بدون snapshot نهائي

الخطة B:
1. افتح ملفك المحلي وانسخ كل ما أُضيف منذ آخر backup.
2. ألصقه في سيشن جديد مع الـ MASTER + هذا الـ Resume Protocol.
3. أعطِ التعليمة: 
   ```
   هذا هو آخر ما أُضيف للملف. حلّله، خمّن أي phase وأي worker أنا فيه،
   وأعطني snapshot مُعاد بناؤه.
   ```
4. اعتمد الـ snapshot المعاد بناؤه واستمر.
